# Bundle: AI SaaS Launch

## Outcome

Prepare an AI-powered SaaS product for a controlled public launch with evidence across value, AI quality, security, privacy, accessibility, reliability, and operations.

## Required capabilities

Project intelligence, critical-journey testing, AI evaluation, prompt-injection testing, abstention and fallback, secrets detection, dependency scanning, authorization testing, privacy mapping, accessibility, observability, backups, incident response, rollback, and launch governance.

## Selection rules

Apply `profiles/ai-saas.md` and the detected stack guides. Prefer existing project tools when adequate. Select registry resources by capability, tier, compatibility, and license. Tier C evaluation tools remain supervised. Do not add multiple overlapping observability or testing systems without evidence.

## Implementation order

1. project assessment and critical journeys;
2. architecture and data flows;
3. deterministic tests and CI;
4. AI evaluation and guardrails;
5. security and privacy controls;
6. accessibility;
7. deployment, monitoring, backup, incident, rollback;
8. launch-readiness verdict.

## Verification

Run critical journeys, adversarial AI evaluations, authorization and tenant tests, data-flow checks, accessibility, production build, preview deployment, provider failures, restore, rollback, and alert delivery.

## Human review

Domain, security, privacy, legal, accessibility, and operations review are required for high-impact AI, regulated data, production access, claims, and launch blockers.
