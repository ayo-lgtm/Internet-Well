# Bundle: Accessibility Baseline

## Outcome

Establish repeatable accessibility coverage for the product's critical journeys across code, automated checks, keyboard use, assistive technology, content, and regression testing.

## Required capabilities

Semantic UI, keyboard access, focus management, accessible names, forms and errors, contrast and zoom, motion controls, media and document access, automated scanning, manual testing, and regression evidence.

## Selection rules

Apply the product and UI stack profiles. Automated tools may triage but cannot establish conformance alone. Prefer resources that integrate with the existing test system and support repeatable critical-journey evidence.

## Implementation order

1. identify critical journeys and assistive-technology needs;
2. fix structural semantics and keyboard blockers;
3. integrate automated checks;
4. test screen-reader and low-vision paths;
5. add regressions and documentation;
6. obtain specialist review for claims.

## Verification

Run automated scans, keyboard-only paths, representative screen-reader tests, zoom and reflow checks, contrast review, form-error behavior, focus order, announcements, and accessible-name inspection.

## Human review

Accessibility specialists and representative users should review public critical journeys and any formal accessibility or legal conformance statement.
