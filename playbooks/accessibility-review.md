# Playbook: Accessibility Review

## Purpose

Verify that people with disabilities can complete the product's critical journeys using representative assistive technologies and input methods.

## Inputs

Project assessment, critical journeys, supported devices and browsers, design system, content, languages, media, forms, documents, and existing accessibility evidence.

## Workflow

1. Identify critical journeys and user groups.
2. Review semantics, headings, landmarks, names, roles, states, focus, keyboard flow, forms, errors, contrast, zoom, motion, media, and documents.
3. Run automated checks as triage, not proof.
4. Test keyboard-only and representative screen-reader paths.
5. Review responsive, touch, low-vision, cognitive-load, language, and error-recovery behavior.
6. Select accessibility resources according to framework and evidence needs.
7. Rank barriers by blocked task, prevalence, severity, and remediation effort.

## Outputs

Journey-based accessibility findings, automated results, manual evidence, selected resources, remediation order, regression tests, known limitations, and conformance claims requiring review.

## Verification

Retest corrected journeys with keyboard and assistive technology; rerun automated checks; verify focus, errors, announcements, zoom, contrast, and accessible names; preserve evidence by browser and tool version.

## Stop conditions

Do not claim full accessibility or formal conformance from automated scans alone. Stop before publishing a conformance statement without competent review.

## Human review

Accessibility specialists and people using relevant assistive technologies should review critical public journeys and any formal legal or conformance claim.
